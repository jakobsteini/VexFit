# B5 – Ladezeit und Stabilität mobil (Dauerlauf 05./06.11.2026)

## Messung (reproduzierbar)

Skript: `rundgang/ladezeit-messung.mjs` (Playwright/Chromium, headless).
Gerät 390×844, mobiler User-Agent; Drosselung **Lighthouse „Mobile Slow 4G"**
(1,6 Mbit/s ↓, 750 Kbit/s ↑, 150 ms RTT, CPU 4×). Für Determinismus werden
Fremd-Hosts (Supabase, Meta) abgebrochen – gemessen wird die **eigene Nutzlast**.
Jede Seite wird mehrfach geladen, berichtet wird der **Median**.

```bash
python3 -m http.server 8799          # im Projektordner, eigenes Terminal
npm i playwright@1.65.0 && npx playwright install chromium   # einmalig
LAEUFE=3 node rundgang/ladezeit-messung.mjs
```

bibliotheken (kein CDN, kein Leaflet/Supabase‑JS im `<head>`), Schriften lokal
mit `font-display:swap`, Seitenskripte als `type="module"` oder am Seitenende
(blockieren das erste Rendern nicht), **keine** `<img>` ohne Maße (Logos sind
Inline‑SVG) – also keine messbaren Layout‑Sprünge durch Bilder.

## Was geändert wurde

- **Supabase vorverbinden** (`<link rel="preconnect">`) auf index.html,
  registrieren.html, trainer.html und trainer-bereich.html. DNS+TLS zu
  `*.supabase.co` werden beim Laden aufgebaut, statt erst beim ersten Aufruf
  (Sitzungsprüfung, Registrier‑POST, Trichter‑Beacon). Spart beim ersten
  API‑Aufruf einen Verbindungsaufbau (unter Slow‑4G‑Latenz ~1 RTT ≈ 150 ms).
  Kostet keine Render‑Bandbreite (nur Verbindungsaufbau, kein Download).

## Was bewusst NICHT geändert wurde (BLOCK/Entscheidung)

- **Schrift‑Vorladen (`preload` der woff2) verworfen.** Getestet auf allen vier
  Seiten; unter Slow‑4G verschlechterte es den FCP messbar (index 0,44 s → 0,54 s,
  registrieren 0,43 s → 0,54 s), weil die Schrift mit der render‑kritischen
  HTML/CSS um die schmale Bandbreite konkurriert. Da `font-display:swap` ohnehin
  sofort mit der System‑Schrift zeichnet, bringt das Vorladen für den sichtbaren
  Erstinhalt nichts und schadet auf langsamen Mobilverbindungen – genau der
  Zielgruppe. Deshalb nicht ausgeliefert.
- **Skripte entfernen:** `vexfit-plz.js` und `vexfit-ziele.js` werden auf
  registrieren.html weiter gebraucht (PLZ‑Auflösung, Spezialisierungs‑Chips) –
  nichts Totes zum Streichen.

Keine Funktion ging verloren; die vollständige Deno‑Testsuite bleibt grün.
